# Require explicit DeepSeek filename analysis

The application must not send filenames to DeepSeek during directory scanning, file loading, selection changes, or other automatic background work. Each filename-analysis request requires an explicit user action for the selected track and may contain only the filename stem plus the fixed response schema and extraction constraints; directory paths, existing tags, cover data, and audio content must not be sent. This trades automatic convenience for a clear privacy boundary, predictable API cost and latency, and uninterrupted local browsing when DeepSeek is unavailable.

While filename analysis is running, the existing full-window loading overlay prevents ordinary selection changes and `Esc` cancels the request. A completion may update the editor only when both its request ID and target file path still match the active request and selected track; any stale or misdirected completion is discarded without changing the editor. The path check remains necessary even though the overlay blocks normal mouse interaction because keyboard focus, programmatic selection, or future UI changes can otherwise detach a result from the track that initiated it.
